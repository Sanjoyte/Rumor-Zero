## Why these choices

- **Placeholders created now: only `backend/.env.example` and `frontend/.env.example`.**
  - `django-admin startproject rumor_zero .` only needs `manage.py` and `rumor_zero/` to be absent, so it won't collide.
  - `create-next-app` *does* refuse a non-empty folder. Its allow-list includes `.gitignore`, `.claude`, `docs` and `LICENSE`, but not `.env.example`. That's why Part 0B moves the file aside for the scaffold step.
  - Scaffold with `--no-agents-md`. Otherwise create-next-app writes `frontend/AGENTS.md` and `frontend/CLAUDE.md`, which would compete with the root shared instructions.
- **`backend/apps/<name>`** keeps the project package (`rumor_zero/`) small, with domain code grouped by feature. The app label stays short (`posts`), and the Python path is `apps.posts`.
- **One `settings.py`, driven by env vars**, not `settings/dev.py` + `settings/prod.py`. It's simpler, and Render and local differ only in `.env` values.
- **Where converted Stitch code goes:**
  - Reusable primitives → `frontend/src/components/ui/`
  - Layout chrome → `frontend/src/components/shell/`
  - Screen-specific compositions → `frontend/src/features/<domain>/`
  - Route files in `src/app/` stay thin: fetch data + compose feature components.
  - Design tokens live **only** in `src/app/globals.css` (`@theme`). Components use token classes (`bg-surface-container-low`, `font-claim-headline text-claim-headline`), never raw hex or Tailwind's default palette. The only exceptions are the generated `src/lib/brand-assets.json` and `src/app/manifest.ts` (brand colours for non-CSS contexts).
- **Brand assets are generated, not drawn.** One master (`design/logo.svg`) and one command (`npm run brand:build`) produce every favicon, icon, share image and email/admin logo. One component (`<Logo/>`) shows the brand, so a logo change is a one-place edit.
- **Profile photos live in Postgres** (`accounts.Avatar`), not in object storage: no new service, no card (ANALYSIS f-7).
